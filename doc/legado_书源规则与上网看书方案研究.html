一、结论速览

① 书源写法：可以研究透，且已从源码还原完整语法规则引擎 AnalyzeRule 的 6 种模式、组合符、@ 指令、URL 选项、规则实体字段、JS 扩展 API、JS 单文件书源契约，全部有源码级依据；本报告给出速查表与可运行示例。
② 订阅源写法：不是「RSS 专用」，而是一个可定制网页阅读器RssSource 有 injectJs、preloadJs、shouldOverrideUrlLoading、ruleContent、contentWhitelist 等字段——源码注释明确写着「可通过 js 调用阅读搜索、添加书架」。
③「上网看书」可实现性：高（约 4/5）内置浏览器、JS 桥接、资源嗅探、规则解析、加入书架、正文缓存、断点续读、WebDAV 同步 几乎全部已存在。缺的只是「把浏览 → 识别 → 落库」串起来的薄薄一层。
④ 推荐路径：轻量集成，不改核心链路在 WebViewActivity 加「识别为书籍」+ 注入嗅探 JS + 一个 PageBookSniffer，生成虚拟书源/章节后调用现有 /saveBook。MVP 约 1–2 人周，难点在长尾站点识别准确率而非平台能力。
执行状态：本轮为源码研究与方案设计，未修改仓库内任何源码，未执行上传、推送、打包或 APK 相关操作。附带产物（报告、两个 PoC 模板）写在 /workspace 交付目录；若要实际改动工程代码，请按既定规则先明确批准。

2.3 规则模式判定（AnalyzeRule.SourceRule.init，源码 647–710 行）

写法模式说明
@CSS:div.list a 或 @@规则Default(Jsoup)强制走 CSS 选择器；@@ 用于避免规则被误判为 XPath
@XPath://h1/text() 或规则以 / 开头XPathHtmlUnit / JsoupXpath 解析
@Json:$.data.list、$.data[*].name、$[0].name，或响应本身是 JSONJsonJsonPath；响应为 JSON 时自动切换
@js:... / <js>...</js> / {{JS表达式}}JsRhino 执行；AppPattern.JS_PATTERN
@webjs:...WebJs在 WebView 内执行 JS 并取结果（WebJS_PATTERN）
##正则##替换 或 $1 捕获组Regex含 ## / $\d 时自动切到正则模式

2.4 规则语法速查表（组合符 / @ 指令 / 变量 / 替换）

语法语义（源码依据）
&& / || / %%规则组合：顺序拼接、取第一个有效结果、合并多元素。RuleAnalyzer.splitRule 用平衡组跳过 [] / () 内的分隔符，不会把选择器里的括号误切。
##match##replace正则替换；##match##replace### 只替换第一个匹配（replaceFirst）。
@put:{"k":"v"}写入变量（splitPutRule，putPattern）。变量挂在 chapter / book / ruleData / source 上。
@get:{k}读变量（evalPattern）。自定义键名避免用 bookName / title（源码提示可能被覆盖）。
{{...}}内嵌 JS 求值，可引用 result、page、key、book、chapter、java.*、source；示例书源用 {{searchPage}}。
$0 / $1 …正则捕获组引用（regexPattern = \$\d{1,2}）。
<js> / @js: / @webjs:JS 规则；<usehtml>…</usehtml> 保持 HTML 不转文本。
-规则订阅列表倒序（RssParserByRule 中 ruleArticles.startsWith("-")）。

2.5 URL 规则语法（AnalyzeUrl.kt）

https://site/search?q={{searchKey}}&p=<1,2,3>,{"method":"POST","body":"{\"title\":\"key\"}","headers":{"X-Token":"..."},"charset":"gbk","timeout":15000,"useWebView":true,"webJs":"...","bodyJs":"...","js":"...","retry":2,"followRedirects":true,"dnsIp":"1.2.3.4","webViewDelayTime":1200,"serverID":"..."}
  • 选项 JSON：URL 后紧跟 ,{...}（paramPattern = \s*,\s*(?=\{)），支持 method(GET/POST/HEAD)、body、headers、charset、type、retry、useWebView、webJs、bodyJs、js（改写 URL）、timeout、followRedirects、dnsIp、serverID、webViewDelayTime。
  • 分页：<p1,p2,p3>（pagePattern），第 N 页取第 N 项，超出取最后一项；也可用 {{page}} / {{searchPage}} 由 JS 计算。
  • 动态渲染站点：useWebView:true + webJs + sourceRegex（BackstageWebView.SnifferWebClient.onLoadResource 用正则嗅探加载资源），可拿到 JS 渲染后的 DOM / 接口地址。
  • POST 表单：body 非 JSON/XML 时按 key=value 自动编码；GET 的 query 也会按 charset 规范化。

3.3 关键能力：URL 拦截（源码注释原文）

RssSource.shouldOverrideUrlLoading 注释：「跳转 url 拦截，js 返回 true 拦截，js 变量 url，可以通过 js 打开 url，比如调用阅读搜索，添加书架等，简化规则写法，不用 webView js 注入」。BackstageWebView.SnifferWebClient 实现了该拦截，并额外支持 sourceRegex 在 onLoadResource 里嗅探资源 URL、overrideUrlRegex 匹配跳转回传结果。这正是「上网看书」需求里最值钱的一块现成基建。

4.2 三条路径

路径做法评价
A 零改动
（纯配置）		用订阅源的 singleUrl + injectJs + shouldOverrideUrlLoading + ruleContent，或手写「通用网页书源」，手动导入。浏览时点脚本把当前页加入书架。✅ 立即可做、零风险；❌ 每个站点要写规则，做不到「自动嗅探任意网页」，适合先验证流程。
B 轻量集成
（推荐）		在 WebViewActivity 增加「识别为书籍」菜单 + 注入嗅探 JS；新增 PageBookSniffer（Kotlin）做结构识别；生成虚拟书源 / Book / BookChapter 后调用 /saveBook 与 /refreshToc；阅读、缓存、进度全复用。✅ 改动集中（3–5 个源文件 + 1 个 JS）、不动阅读核心、可灰度；MVP 约 1–2 人周，准确率打磨另需 2–4 周。
C AI/MCP 增强在 B 之上新增 MCP 工具 sniff_page / save_sniffed_book：把 DOM 摘要交给 AI 生成书源规则，再走已有 save_source 落库；长尾站点由 AI 兜底。✅ 与这版已有的 MCP Server 天然契合，解决「通用规则难写」；❌ 依赖模型/联网，作为 B 的补充而非替代。

4.3 推荐架构（B 方案分层）

① 采集层  WebViewActivity.onPageFinished → evaluateJavascript(sniff.js)
          → 回传 JSON：{ title, url, links[], candidates{正文容器}, nextUrl, meta }
② 识别层  PageBookSniffer.analyze(json)
          - 页面类型判定：目录页（章节链接密度高）/ 正文页（单块长文本 + 上一章/下一章）
          - 章节候选：<a> 文本命中 txtTocRule 26 条正则 + 同路径前缀聚类
                     + 序号连续性校验 + 去除导航/推荐位
          - 正文候选：文本密度（文本长度/标签数）最大块，兼容 #content/.article 等常见 id
          - 书名/作者：<title>、h1、og:title、nameAuthorPatterns（LocalBook 已有）
③ 规则层  SniffedBookBuilder
          - 生成虚拟 BookSource（bookSourceUrl=站点域名，规则用 @css:/@js:）
          - 或直接生成 BookChapter 列表（更稳，避免二次解析误差）
          - 生成 ContentRule（content / nextContentUrl / webJs / sourceRegex）
④ 落库层  POST /saveBook (Book JSON, type=text, origin=虚拟书源, bookUrl=目录页URL,
          可先置 BookType.notShelf 试读) → POST /refreshToc 或直插 BookChapter
          → BookHelp.saveContent 缓存正文
⑤ 阅读层  ReadBookActivity（原样） + durChapterIndex/durChapterPos + ReadRecord
          + AppWebDav 跨设备续读 + /saveBookProgress 供 Web 端同步

① 注入的嗅探 JS（返回结构，不改动页面）

(() => {
  const chapterRe = /第\s*[0-9〇零一二两三四五六七八九十百千万壹贰叁肆伍陆柒捌玖拾佰仟]+\s*[章节回卷集部篇]|序章|楔子|番外|尾声/;
  const links = [...document.querySelectorAll('a[href]')]
    .map(a => ({ title: (a.innerText || '').trim(), url: a.href }))
    .filter(x => x.title && chapterRe.test(x.title) && x.url.startsWith(location.origin));
  const blocks = [...document.querySelectorAll('div,article,section')]
    .map(el => ({ el, score: el.innerText.length / (el.getElementsByTagName('*').length + 1) }))
    .sort((a,b) => b.score - a.score);
  return JSON.stringify({
    title: document.title, url: location.href,
    chapters: links,
    contentSelector: blocks[0] ? cssPath(blocks[0].el) : null,
    nextUrl: document.querySelector('a[rel=next], .next, #next')?.href || null
  });
})();
