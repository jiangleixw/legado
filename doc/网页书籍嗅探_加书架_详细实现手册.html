4. 阶段一：网页嗅探（发现「这是一本书」）

4.1 触发点

在 WebViewActivity 菜单 R.menu.web_view 增加 menu_sniff_book；同时可在 onPageFinished(L525) 做静默预嗅探（只在结果达标时显示角标，不打扰用户）。注入方式复用现有 evaluateJavascript，无需新增 WebView。

// WebViewActivity.kt（示意）
R.id.menu_sniff_book -> {
    currentWebView.evaluateJavascript(SNIFF_JS) { value ->
        // evaluateJavascript 返回的是 JSON 字符串再包一层，需两次解析
        val raw = GSON.fromJsonObject<String>(value).getOrNull() ?: return@evaluateJavascript
        val result = GSON.fromJsonObject<SniffResult>(raw).getOrNull() ?: return@evaluateJavascript
        PageBookSniffer.analyze(result)   // → 弹确认窗
    }
}

4.3 置信度评分模型（建议）

信号权重说明
章节候选链接数 ≥ 5+35目录页最强信号
章节链接 URL 路径同构（同目录、仅尾号递增）+20如 /book/123/1.html → /2.html
章节序号连续（第1章…第N章 无跳号）+15中文数字需先归一化
正文块文本 ≥ 800 字且链接密度低+15正文页信号
存在「目录/章节/最新章节/开始阅读」等锚文本+8站点语义
og:type=book / JSON-LD @type=Book / __NEXT_DATA__ 含 chapters+7结构化数据，命中即高可信
命中「下一章」且指向同构 URL+5连载结构

阈值建议：≥ 60 直接弹确认窗（预填书名/目录）；40–60 弹「可能是书籍，请确认」；< 40 不提示（可手动强制识别）。评分逻辑放 Kotlin 侧，JS 只负责采集，便于后续调参而不必重新注入。

4.4 动态渲染 / 反爬站点的处理

  • JS 渲染目录：嗅探在 onPageFinished 之后执行，DOM 已就绪；若站点延迟加载，可延时 300–800ms 再注入，或监听 MutationObserver 后回调。
  • 需要 WebView 取源：URL 规则加 ,{"useWebView":true,"webJs":"...","sourceRegex":"..."}；AnalyzeUrl 会用 BackstageWebView 渲染后取 HTML，sourceRegex 从网络资源里嗅探真实数据接口。
  • 登录/Cookie：内置浏览器已共享 enabledCookieJar 与 WebCacheManager，嗅探到的书源默认带上当前 Cookie，无需重复登录。

5. 阶段二：目录分析

5.1 三条证据链（互相校验）

  1. DOM 章节链接：嗅探脚本给出的 chapters[] 是主来源。
  2. 内置 26 条章节正则：assets/defaultData/txtTocRule.json，覆盖「目录/目录(去空白)/目录(匹配简介)/数字(纯数字标题)/大写数字/数字混合/数字 分隔符 标题名称/…」。即使页面没有 <a>（纯文本目录），也能用 TextFile 的切章算法切分。
  3. URL 模式 + 序号连续性：对候选 URL 做路径聚类，提取变长数字段；若序号连续递增，则判定为同一本书的章节序列，并可推断缺失章节。

5.3 分页目录与去噪

  • 分页目录：把 nextUrl 写入 ruleToc.nextTocUrl，让 WebBook 自动翻页合并（模板里是 @css:a.next@href）。
  • 去噪：剔除「上一页/下一页/返回目录/加入书签/广告/推荐」等锚文本；剔除与正文 URL 不同构的外链；同源约束已在 JS 侧做第一层。
  • 卷/章层级：TocRule 有 isVolume、formatJs，可把「第一卷 xxx」识别为卷节点。
  • 兜底：确认弹窗里目录可编辑、可拖拽排序、可删行。识别不准时用户手动修一次，比追求 100% 自动识别更实用。

6. 阶段三：生成虚拟书源

为什么必须生成「虚拟书源」？Book 实体用 origin 字段指向 bookSourceUrl，WebBook 靠它取规则去解析目录与正文。直接塞章节列表而不建书源，会导致「目录能显示、正文取不到、刷新目录失效」。因此正确做法是：为这个站点生成一份最小可用的 BookSource 并落库，再让 Book 指向它。

7.3 试读 → 正式入架（关键机制）

BookType.notShelf = 0b100_0000_0000 (1024)，源码注释原文：「未正式加入到书架的临时阅读书籍」。推荐两步走，与 api.md 的「先插入书籍以启用缓存，试读后决定不添加请删除书籍」完全一致：

  1. 试读：type = text or notShelf（8 | 1024 = 1032）插入 → 缓存与目录立即可用，但书架列表不显示。
  2. 确认：用户读几章后点「加入书架」→ 清掉 notShelf 位（type = 8）→ book.update()。
  3. 放弃：POST /deleteBook（BookController.kt L265 之后）清理试读数据。
零改动点：book.save() / book.update() / book.delete() 都是 Book 实体已有的扩展方法，Room DAO、AutoMigration、书架 UI 全部不用动。也可以不走 HTTP，直接在进程内 appDb.bookDao.insert(...)，更简单（HTTP 是给外部/AI Agent 用的）。

// PageBookSniffer.kt（骨架）
object PageBookSniffer {
    fun analyze(r: SniffResult): SniffCandidate? {
        var score = 0
        if (r.chapters.size >= 5) score += 35
        val shape = r.chapters.groupBy { it.url.path.replace(Regex("""\d+"""), "#") }
                              .maxByOrNull { it.value.size }
        if ((shape?.value?.size ?: 0) >= 3) score += 20
        if (isSerialContinuous(r.chapters)) score += 15
        if (r.contentText.length > 800) score += 15
        if (score < 40) return null
        return SniffCandidate(
            title   = r.meta.ogTitle.ifBlank { r.meta.h1.ifBlank { r.title } },
            author  = r.meta.author,
            chapters= mergeWithBuiltinTocRules(r.chapters, r.contentText), // 26 条正则兜底
            tocSelector   = commonParentSelector(r.chapters),
            contentSelector = r.contentSelector,
            nextUrl = r.nextUrl,
            confidence = score
        )
    }
}

// SniffedBookBuilder.kt（骨架）
suspend fun build(c: SniffCandidate, site: String): Pair<BookSource, Book> {
    val srcUrl = "$site#sniff-" + c.title.hashCode().toString(16)
    val source = BookSource(
        bookSourceUrl = srcUrl,
        bookSourceName = "网页嗅探·" + site.toUri().host,
        bookSourceGroup = "嗅探", bookSourceType = 0, enabled = true,
        ruleToc = TocRule(
            chapterList = "@css:${c.tocSelector} a", chapterName = "text",
            chapterUrl = "href", nextTocUrl = "@css:a.next@href"),
        ruleContent = ContentRule(
            content = "@css:${c.contentSelector}@html",
            replaceRegex = "##<script[\\s\\S]*?</script>##")
    )
    appDb.bookSourceDao.insert(source)
    val book = Book(
        bookUrl = c.tocUrl.ifBlank { c.url }, tocUrl = c.tocUrl,
        origin = srcUrl, originName = source.bookSourceName,
        name = c.title, author = c.author,
        type = BookType.text or BookType.notShelf,   // 先试读
        totalChapterNum = c.chapters.size, canUpdate = true
    )
    book.save()                       // 或 POST /saveBook
    appDb.bookChapterDao.insert(*c.chapters.toTypedArray())
    return source to book
}

11. 风险、边界与合规

风险缓解
站点结构差异大，自动识别误判置信度阈值 + 26 条内置正则 + URL 聚类 + 序号连续性 + 目录可编辑 + AI 兜底（路径 C）
动态渲染 / 接口取数useWebView + webJs + sourceRegex、BackstageWebView 取渲染后 DOM
章节 URL 时效 / 连载更新refreshToc + nextTocUrl 自动补章；bookUrlPattern 限定范围
同名书源冲突bookSourceUrl 带站点 + 路径指纹哈希；入库前查重
付费/登录墙、反爬只复现浏览器已能正常看到的内容，不绕过付费、不破解加密、不高频抓取
版权合规仅限个人合法阅读与本地缓存；不提供批量下载、不分发内容、不内置任何站点书源。GPL-3.0 衍生工程需注意相应的开源义务
隐私嗅探脚本只读 DOM、不发请求；不上传浏览历史；进度同步走用户自配 WebDAV
越界提醒：本方案是「把用户自己正在浏览的网页，整理成 App 内的阅读条目」，属于阅读器体验增强。任何「批量爬取全网小说、绕过付费、去除版权声明」的用法都不在方案范围内，也不建议实施。
